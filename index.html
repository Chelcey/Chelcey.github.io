Project 2:

Don’t Get It Twisted (Tongue Twister App)

Class: Social Computing

Objective: To design an engaging, challenge-based platform for users to improve pronunciation through live tongue twister competitions.

Overview:
We created a tongue twister app that promotes clear speech, confidence, and fun through community-driven challenges. The project moved from concept to in-person prototypes with user feedback shaping every iteration.

Research & Inspiration:

  • Conducted surveys with students, language learners, and gamers to identify pronunciation-related challenges.
  • Analyzed existing language learning and voice-based gaming tools to identify gaps.

Design Process:

Wireframes:

  • Designed screens for sign-up, home, viewer mode, sudden death challenge, and user profiles.
  • Prioritized intuitive navigation and an engaging interface.

Prototypes:

  • Version 1: Simulated gameplay using a Discord bot — too complex for real-time facilitation.
  • Version 2: Hosted in-person competitions using Slido for voting and feedback — improved engagement.
  • Version 3: Final prototype refined based on user input — focused on ease of use and fun.

Final Design Features:

  • Personalized practice exercises
  • Live competitions with real-time audience voting
  • User profiles with stats
  • Clear instructions and immediate performance feedback

Tools & Role:

My Role:

  • Conducted background research and surveys
  • Co-created presentation slides and final documentation
  • Contributed to analog and digital prototyping decisions

Tools Used:

  • Figma (UI design)
  • Slido (audience voting)
  • Google Slides (presentation)
  • Discord (early prototype simulation)

User Feedback:

  • Preferred in-person competition over Discord simulation
  • Enjoyed interactive challenges and public speaking
  • Suggested clearer instructions and real-time feedback
  • Emphasized fair judging based on accuracy over speed

Key Takeaways:

  • Iteration and user feedback were crucial in shaping a more inclusive and engaging design
  • Simplicity and clarity proved more valuable than over-engineering features
  • Real-world testing offered deeper insights than digital-only prototyping
